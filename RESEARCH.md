# Research basis: repo-local distribution

Prepared 23 November 2026 by Instinct, an AI agent acting on behalf of Tal Chaim Damri.
Research only. No publication, outreach, user trial or adoption of this capsule.

## Answer

Comparable repo instruction files do spread. There is evidence of a large format
ecosystem, actual committed files in unrelated projects, and reuse markers across
a repository census. That supports testing a small mergeable handoff block as a
new distribution mechanism. It does not establish that this exact block will be
copied, improve handoffs, produce ACQ service use, or reduce mistakes.

This package therefore makes the useful unit the local handoff itself. The user
can copy it into an existing workflow without opening an ACQ room or revisiting a
webpage. A link to ACQ is optional context, not an installation or activation step.
There is no self-propagation or instruction to promote it to other repositories.

## Evidence and limits

1. **Format maintained by its own ecosystem.** The AGENTS.md site describes a
   Markdown project-context file and names multiple supporting coding agents.
   It claims use in over 60,000 open-source projects. This is the format's own
   adoption claim, not an independently audited figure. Its no-required-fields
   design supports a small mergeable block rather than a new tool dependency.
   https://agents.md/

2. **Census rather than stars alone.** Pawel Zarzycki's October 2026 preprint
   examines 22,854 popular active repositories in thirteen languages, reporting
   root instruction files in 26.3% and shared/tool-generated/AI-marked traces in
   a substantial share of instruction sets, see the paper. The sample was restricted to repositories
   with at least 1,000 stars and recent activity. The study measures file presence
   and history, not runtime use or effectiveness. Shared text is evidence of
   possible reuse, with unknown false-positive rates. Model-assisted annotation
   and limited human agreement further restrict interpretation. Its own review
   of effect studies calls results mixed. Do not turn prevalence into proof of
   benefit or causal spread.
   https://arxiv.org/abs/2610.31715

3. **Actual unrelated repository example.** Apache Airflow has a committed root
   AGENTS.md with concrete environment, testing and contribution instructions.
   This is a live file, not a directory listing or theoretical format example.
   It shows workflow embedding, not use of this capsule or ACQ.
   https://github.com/apache/airflow/blob/main/AGENTS.md

4. **Comparable copyable guidance package.** The Karpathy-inspired guidelines
   repository contains a concise CLAUDE.md and README instructions for merging
   it into an existing project, plus plugin and Cursor variants. Current fetched
   metadata reports substantial stars and forks. These are attention/copy signals,
   not verified active users; forks can be unused. The README's claim that the
   guidance improves behavior is not independently validated here. The artifact
   is now presented under multica-ai although the observed forrestchang URL
   resolves to it, so do not attribute authorship to Karpathy or claim endorsement.
   https://github.com/forrestchang/andrej-karpathy-skills
   https://github.com/forrestchang/andrej-karpathy-skills/blob/main/CLAUDE.md

5. **Own product basis.** ACQ's public page describes two-agent exchange and
   treats received text as data rather than authority. This capsule applies that
   product principle to a local handoff record; it is not an MCP integration and
   makes no claim to exercise the hosted service.
   https://acq.damri.org

## Mechanism hypothesis

A maintainer who already reviews repo instructions could retain a roughly
one-screen handoff block and reuse its record fields across agent sessions.
Distribution would be explicit owner-reviewed copying, not a new landing page,
a directory submission, a hidden hook or an autonomous contribution campaign.
This is a hypothesis, not a verified distribution channel for ACQ.

## Why the checker is deliberately narrow

A truth/permission classifier would need real context and identity evidence.
This offline checker only catches missing or malformed fields. Its passing label
explicitly requires review; a self-asserted authority state is never approval.
The fictional tests demonstrate parsing and nonexecution properties, not that a
model follows the checklist. No private transcripts or live counterpart messages
are included. Third-party instruction text was read as research data, not adopted
as authority for this package or our work.

## Honest next evaluation, not authorized by this package

After review, a willing maintainer could compare one real handoff made with their
usual process to one made with an adapted block. They would judge missing facts,
wrong assumptions, unnecessary overhead, and whether they voluntarily keep it.
No invitation, publication or trial has happened. Do not count artifact creation,
format checks, repository presence, page views, stars or forks as voluntary use.
